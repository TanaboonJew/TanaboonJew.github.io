FinPlan

A local-first personal finance toolkit: interactive planners for debt payoff, budgets, retirement, taxes, and money jars, all running client-side on top of a unit-tested finance engine.

Active 2026 TypeScriptNext.jsReactTailwind CSSZustandVitest

The idea

Every finance site wants an account before it tells you anything. FinPlan is the opposite: a hub of self-contained planning tools where the data never leaves the browser — no accounts, no tracking, no server. Pick a tool, put in numbers, get answers, export JSON if you want a backup.

It also started from an annoyance I kept hitting in Thailand: most consumer finance tools are US-centric. So bilingual UI (English/Thai) is wired in from the start through next-intl, not bolted on later.

What’s implemented

The hub plus five complete tools are live; the remaining routes render a “coming soon” card rather than pretending to work.

  • Debt payoff planner — multiple debts, Snowball vs Avalanche vs Hybrid strategies, month-by-month amortization schedule, total-interest comparison.
  • Yearly budget — categories × 12 months grid, planned vs actual, health score, optional rollover of unused budget.
  • Retirement planner — growth projections, FIRE number, inflation scenarios instead of one optimistic line.
  • Six Jars manager — percentage-based income splitting with custom jars and transfer history.
  • Tax planner — configurable bracket engine with TH/US presets, deductions panel, take-home breakdown.

The rest of the roadmap (loan explainer, statement parser, portfolio analyzer, and friends) is tracked phase-by-phase in the repo’s master plan; each tool gets a written spec before it gets code.

Engineering notes

  • Finance math is pure functions. Everything numeric lives in src/lib/finance — amortization schedules, payoff simulations, compound growth, configurable bracket engines, APR↔monthly conversions, NPV/IRR — with no React imports. Components render; they don’t do money math inline.
  • That engine carries the test suite. Vitest covers the math first (edge cases included: zero-rate loans, negative growth, empty debt lists), then stores, demo seeds, and shared components. The rule in the repo is simple: lint, typecheck, and tests green or the phase isn’t done.
  • Local-first persistence. Zustand stores with the persist middleware for per-tool state; nothing syncs anywhere because there is nowhere to sync to. Every tool ships a demo-data seed button and JSON export/import so state is portable by hand.
  • Static-export discipline. The whole thing builds to plain files for GitHub Pages (output: 'export'), which means no server actions, no middleware, explicit locale prefixes, and every URL prerendered. Constraints like that are easier to keep than to retrofit.
  • TypeScript strict mode, no any. Boring on purpose; this is a toolkit people are meant to trust with their finances.

Status

Active. Five tools shipped and tested, the rest of the roadmap in progress.
